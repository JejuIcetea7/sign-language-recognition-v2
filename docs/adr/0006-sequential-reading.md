# 0006 영상 읽기를 순차 읽기로 변경

## Status  
Proposed  


## Context  
- 기존 메인 파이프라인은 프레임 번호마다 `cap.set(CAP_PROP_POS_FRAMES)`로 이동해 읽었다(seek).
- 순차 읽기(앞에서부터 `grab()`으로 넘기며 필요한 프레임만 `retrieve()`)와 비교했다. ([실험 0005](../experiments/0005-reading-method.md))

| | seek | 순차 읽기 |
|---|---|---|
| 24프레임 읽기 시간 p50 | 1944 ms | 299 ms |
| 24프레임 읽기 시간 p95 | 2236 ms | 342 ms |

- 두 방식이 읽은 프레임은 영상 220개 중 5개(2.3%)에서 달랐다. (프레임 5280개 중 47개)
- 학습 데이터(`features_24.csv`)는 순차 읽기로 만들었다.


## Decision  
메인 파이프라인의 영상 읽기를 순차 읽기로 한다.


## Consequences  
- 학습과 서빙이 같은 방식으로 프레임을 읽는다. 재추출과 재학습은 필요 없다.
- 읽기 시간이 약 1/6.5로 줄어든다.
- 읽는 마지막 프레임까지 모든 프레임을 디코딩한다. 앞 3초까지만 읽으므로 영상 길이와 상관없이 일정 범위로 제한된다.
- 어느 방식이 영상의 정확한 n번째 프레임인지는 확인하지 않았다.
- Latency는 이 방식으로 다시 측정한다.
