# 0005 시퀀스 길이를 24프레임으로 변경

## Status  
Proposed  


## Context  
- 기존 파이프라인은 영상당 앞 3초에서 6프레임을 뽑았다(0.5초 간격).
- 6, 12, 24, 48, 60프레임을 같은 조건(GRU, 5-fold, seed 3개)으로 비교했다. ([실험 0004](../experiments/0004-sequence-length.md))

| 프레임 | Macro-F1 평균 |
|---|---|
| 6 | 83.70% |
| 12 | 86.62% |
| 24 | 88.85% |
| 48 | 89.79% |
| 60 | 86.49% (seed 42에서 학습 실패 1건 포함) |

- 선택 규칙(실험 전에 정함): 평균이 가장 높은 길이와 1%p 미만 차이인 길이 중 가장 짧은 것을 고른다.
- 48프레임이 가장 높고, 24프레임은 0.94%p 낮아 규칙에 해당한다.


## Decision  
시퀀스 길이를 **24프레임**으로 한다.


## Consequences  
- 메인 파이프라인(특징 추출, 데이터 로드, 학습, 서빙)을 6프레임에서 24프레임으로 바꾼다.
- 6프레임으로 학습한 기존 모델(`gru.joblib`)은 새 파이프라인과 호환되지 않는다. 24프레임으로 학습한 모델(`gru_24f.joblib`)을 쓴다.
- 영상 읽기와 MediaPipe 호출이 프레임 수에 비례해 늘어나므로 서빙 지연이 늘어난다. 읽기 방식 실험 후 Latency를 다시 측정한다. ([video-reading](../video-reading.md))
- 24와 48의 차이(0.94%p)는 기준 1%p에 가까운 경계 값이다.
- 사람 단위 평가가 아니라는 한계는 그대로다. ([ADR 0004](0004-same-person-in-evaluation.md))
