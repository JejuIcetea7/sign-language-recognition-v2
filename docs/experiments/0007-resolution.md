# 0007. 입력 해상도 줄이기

실험 전에 작성한 계획이다. 결과는 아직 없다.  
현재 지연: [0006](0006-latency-24f-sequential.md) (MediaPipe 266 ms, 영상 읽기 208 ms)


## 목적
프레임 수(24장)는 그대로 두고, MediaPipe에 넣는 이미지 한 장의 크기(해상도)를 줄여서 처리 시간이 얼마나 줄고, 성능(Macro-F1)이 얼마나 달라지는지 확인한다.


## 설정
- 영상은 모두 1920x1080이다. 현재는 이 크기 그대로 MediaPipe에 넣는다.
- 비교 대상: 가로 크기 1920(현재), 960, 640, 480, 320. 비율은 유지하고, 영상을 읽은 뒤(디코딩 후) 줄인다.
- 키포인트 거리는 원본 크기(1920x1080) 기준 픽셀로 계산한다. 줄인 이미지의 크기로 계산하면 거리 값의 크기가 달라져서 학습한 모델과 맞지 않는다.
- 고정 조건: 24프레임, 순차 읽기, GRU (`hidden_size 384, num_layers 2, dropout 0.3, epochs 200, lr 0.001`), -1 채우기


## 측정
1. **속도:** 영상 220개([0005](0005-reading-method.md)와 같은 영상)에서 해상도마다 MediaPipe 구간 시간과 전체 특징 추출 시간을 p50, p95로 잰다. 영상마다 4번 실행하고 첫 번째는 버린다.
2. **특징 변화:** 같은 영상 220개에서 원본 해상도 특징과의 차이를 잰다. 손이 인식되지 않는 프레임 비율(NaN)의 변화도 기록한다.
3. **성능:** 해상도마다 영상 1272개의 특징을 다시 추출하고, GRU를 5-fold로 학습해 Macro-F1과 Accuracy를 잰다. seed 3개(42, 7, 123)를 같은 seed 안에서 비교한다. 1920(현재)은 0004의 24프레임 결과를 재사용한다.


## 선택 기준
- Macro-F1의 seed 평균이 현재(1920)와 1%p 미만 차이인 해상도 중 가장 작은 것을 선택한다.
- 1%p 이상 떨어지면 현재 해상도를 유지한다.
