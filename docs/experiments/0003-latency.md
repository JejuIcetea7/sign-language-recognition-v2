# 0003. Latency와 동시요청 측정 (6프레임, seek 읽기)

측정 코드: `src/benchmark.py`  
환경: 개발 맥 (Apple M5), CPU 추론, 영상 1개(`person1_add (1).mp4`)를 반복 호출, 워밍업 1회 제외  
실행: `python -m uvicorn --app-dir src server:app --port 8000` 후 `PYTHONPATH=src python src/benchmark.py 영상경로`


## 결론
**병목은 모델이 아니라 영상 읽기다.** 영상 읽기가 전체의 약 86%, MediaPipe가 약 14%, 모델은 0.1%다.  
동시 접속을 늘려도 처리량은 약 2 req/s로 고정이고 지연만 접속 수에 비례해 늘어난다 (서버가 요청을 하나씩 처리하기 때문).


## 구간별 (n=20)

| 구간 | p50 | p95 |
|---|---|---|
| 영상 읽기 (6프레임 seek + read) | 427.5 ms | 455.7 ms |
| MediaPipe (6프레임) | 70.3 ms | 74.7 ms |
| 모델 (GRU) | 0.6 ms | 0.8 ms |
| 합계 | 497.9 ms | 529.0 ms |


## 엔드투엔드 (HTTP, 동시 1, n=20)

p50 482.4 ms, p95 488.0 ms  
구간 합계와 거의 같다. 업로드와 임시 파일 저장 오버헤드는 이 환경에서 무시할 만하다. (로컬 접속이라 네트워크 시간은 빠져 있다)
