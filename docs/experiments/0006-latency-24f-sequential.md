# 0006. 지연 시간과 동시요청 재측정 (24프레임, 순차 읽기)

실험 전에 작성한 계획이다. 결과는 아직 없다.  
이전 측정: [0003](0003-latency.md) (6프레임, seek 읽기, 영상 1개)


## 목적
현재 메인 파이프라인(24프레임, 순차 읽기, GRU)의 지연 시간과 동시요청 처리량을 측정한다.


## 설정
- 대상: 22개 단어에서 10개씩, 영상 220개 ([0005](0005-reading-method.md)와 같은 영상)
- 환경: 개발 맥 한 대(CPU), 서버 프로세스 1개
- 측정 코드: `src/benchmark.py`


## 측정
1. **구간별:** 영상 읽기(`read_frames`), MediaPipe(`extract_frame_features`), 모델(`predict`)의 시간을 각각 잰다. 영상마다 4번 실행하고 첫 번째는 버린다. (영상 220개 x 3회 = 660개 값)
2. **엔드투엔드:** 영상을 서버 `/predict`에 올려 응답을 받을 때까지의 시간을 잰다. 요청은 한 번에 1개씩 보낸다. 구간별과 같은 방식으로 영상마다 4번 보내고 첫 번째는 버린다.
3. **동시요청:** 동시 접속 1, 2, 4, 8에서 초당 처리량과 요청 시간을 잰다. 접속 수 x 10개 요청을 보내고, 영상은 220개에서 돌아가며 고른다.

기록은 모두 p50, p95로 한다. 구간별과 엔드투엔드는 하나의 프로세스로 순서대로 측정한다.

## 한계
- 동시요청은 접속 수 x 10개 요청이라 동시 접속이 많을수록 표본이 작아 p95가 불안정하다. (동시 접속 8은 요청 80개)
- 전체 측정을 한 번만 하며, 개발 맥 한 대의 결과이다.
- 서버와 클라이언트가 같은 기계에서 CPU를 나눠 쓰고, 네트워크 시간은 포함하지 않는다.
